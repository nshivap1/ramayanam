# SHABDA — declension paradigms (शब्दरूपाणि)

173 full declension tables (8 vibhaktis × 3 vacanas) for nouns, adjectives, pronouns and numerals.
Games import from `@content/shabda` (or `src/content/shabda`):

```ts
import { SHABDA, shabda, form, shabdaForLevel, meta } from '@content/shabda';
form(shabda('rama-m')!, 3, 1); // ['रामेण']
form(shabda('mati-f')!, 4, 1); // ['मत्यै', 'मतये']  — display form first, every member is a correct answer
form(shabda('tad-m')!, 8, 1);  // []                 — the cell does not exist
```

`level` says when a Samskrita Bharati learner typically meets the table: 1 Śibira (बालक, फल, लता, नदी, तद्, एतद्, किम्, अस्मद्, भवत्/भवती),
2 Praveśa (the remaining vowel stems, core pronouns, numerals, राजन् नामन् मनस् भगवत्), 3 Paricaya (most consonant stems),
4 Śikṣā (participles, rarer stems). The mapping follows `docs/research` (the official syllabi are only published at headline level) and is a
teaching judgement, not a fact about the language — see REVIEW.md.

## Conventions

- Unicode NFC Devanagari, validated with `validateDeva`; one word per form.
- `forms[vibhakti-1][vacana-1]`; row 8 (index 7) is sambodhana **without** the particle हे.
- `Forms[0]` is the conventional textbook form; the others are optional forms (vikalpa) that must be accepted as answers:
  मत्यै / मतये, धेन्वै / धेनवे, नाम्नि / नामनि, राज्ञि / राजनि, स्त्रियम् / स्त्रीम्, श्रीणाम् / श्रियाम्, एतम् / एनम्, माम् / मा, तुभ्यम् / ते, अष्ट / अष्टौ, मनःसु / मनस्सु …
  Ordering rules: full pronoun before enclitic; नदी-type ending before the हरि-type one in इ/उ feminines; syncopated अन्-stem form first; ः-form before the assimilated स्स/ष्ष form.
- `[]` = the cell does not exist: vocatives of pronouns and numerals (deliberately empty, also for सर्व / अन्य / भवत् where grammar books allow one),
  singular/plural of द्वि, singular/dual of त्रि … दशन्, कति, अप्.
- Spelling: class nasal before a stop (गच्छन्तम्, पञ्च); anusvāra before श ष स ह (मनांसि, विद्वांसः); word-final म् (never ं); visarga for final स्/र् (पितः, गीः);
  only the pausa form of a final stop (रामात्, वाक्, तत् — not the sandhi doublets रामाद्, वाग्, तद्).
- Stems in सकारान्त naming: आशिस्, हविस्, धनुस्, चक्षुस्, आयुस्, ज्योतिस् (some tables call these षकारान्त: आशिष्, धनुष् …).
- `gender` of अस्मद् / युष्मद् / पञ्चन् … दशन् / कति is `'m'` with `genderless: true` (same forms in all genders).

## How it was verified

Nothing in `data.ts` is typed by hand. `tools/content/nominal/gen-shabda.ts` derives every cell from reference datasets and keeps a form only
when **two independent source families** attest it; where the Pāṇinian engine data exists for the paradigm it must be one of the two.

| Family (tag in `provenance.verifiedBy`) | Dataset | Licence | Paradigms |
|---|---|---|---|
| `oracle:ashtadhyayi-com(vidyut-prakriya)` | ashtadhyayi.com `shabda/data2.txt` — generated by the Pāṇinian engine vidyut-prakriya | no LICENSE file; README grants use with credit (vidyut itself: MIT) | 170 (+3 by model, below) |
| `oracle:heritage-huet(csl-inflect)` | Gérard Huet's Sanskrit Heritage declensions, `sanskrit-lexicon/csl-inflect/huetdata/nominals/huet_noun_tables.txt` | LGPL-3.0 (data: LGPLLR) | 155 |
| `oracle:csl-inflect-pydecl` | csl-inflect hand tables for pronouns, cardinals, irregulars (`nominals/pydecl/*_data.txt`) | LGPL-3.0 | 41 |
| `oracle:learnsanskrit-kale` / `…-kale-endings` | learnsanskrit.org tables hand-entered from M. R. Kale, *A Higher Sanskrit Grammar* (`sanskrit/data`); whole-word tables, or the ending table of the stem class applied to the stem | CC0 | 54 / 73 |
| `model:ashtadhyayi-com(vidyut-prakriya)` | बालक, पुस्तक, बालिका are not headwords in ashtadhyayi.com; they are declined by substituting the stem into देव / फल / लता and re-deriving ṇatva, then confirmed against Heritage and/or Kale's endings | — | 3 |

Combination counts: four families 30 · three 90 · two 53 (vidyut + Heritage 41, vidyut + Kale 11, vidyut + Cologne 1). No paradigm rests on a single family.
Only facts (inflected forms) are stored; no dataset text is vendored. The datasets are **not** needed to build or test the app.

What the generator does with disagreements (full list in `tools/content/nominal/reports/shabda-report.md`):

- **Sandhi doublets** (रामाद्, वाग्, तद् …, 85 forms): not separate answers → left out.
- **Heritage-only forms** (341): the Heritage table merges homonymous and Vedic stems (राजन् + राज-, नदी + वृकी-type, सखाया, मातरः as acc. pl.) → left out.
- **Single-source forms** (29): typos / misfiled rows in the Kale CSV (अमीनाम्, सखीषु, षष् …), Vedic त्रीणाम्, optional धुट् forms सम्राट्त्सु / षट्त्सु → left out.
- **Accepted on one family + a stated rule** (24, all listed in REVIEW.md): the assimilated locative plural (मनस्सु, धनुष्षु — 8.3.36),
  the optional guṇa vocative of neuter इ/उ stems (वारे, मधो, वस्तो, अश्रो) and हे ब्रह्मन् beside हे ब्रह्म.
- One real disagreement between sources: Heritage prints महान् for the vocative of महत्; vidyut and Kale give हे महन् (kept).

Tests (`node tools/test.mjs unit src/content/shabda`):
`shabda.test.ts` — shape, NFC/`validateDeva`, spelling conventions, syncretism invariants, empty cells, ṇatva / ṣatva / vikalpa / numeral spot checks, coverage;
`golden.test.ts` — 20 tables written out by hand from the textbook paradigms (राम फल रमा हरि नदी गुरु पितृ राजन् तद् अस्मद् युष्मद् + 9 more);
`oracle.test.ts` — re-derives everything from the datasets when `SAMSKURU_ORACLES` (default `/home/claude/refs/data`) exists, checks that `data.ts`
is byte-identical to the regenerated output, that every stored form has two attesting families, and pins the known source disagreements; skipped otherwise.

## Adding a paradigm

1. Add one line to `tools/content/nominal/shabda-spec.ts` (id, stem, gender, kind, anta, meaning, level; `a:` when ashtadhyayi.com has several entries for the word).
2. `node --import tsx tools/content/nominal/gen-shabda.ts` — the paradigm is dropped (and reported) unless two source families cover every cell.
3. Read the new block in `data.ts` and the paradigm's lines in `tools/content/nominal/reports/shabda-report.md`; never hand-edit `data.ts`.
4. Add it to the "awaiting human review" table in REVIEW.md; run the tests.

## Known gaps

- No feminine tables for pronominal adjectives beyond सर्वा / अन्या / एका, no feminine participles (गच्छन्ती), no reduplicated śatṛ (ददत्) and no पुर् — both were dropped because no second source family has them, पुंस्, दिव्, उभ, numerals above 10 (विंशति … are ordinary इ / त् stems), no comparatives in -तर/-तम (regular अ-stems).
- Vocatives of pronouns/numerals are always empty (see Conventions).
- मत्तः / त्वत्तः (tasil forms used for the ablative) are not listed in the 5th case.
- The pack lists forms, not usage: it does not say that भवान् takes a third-person verb, or which optional form is commoner in speech.
