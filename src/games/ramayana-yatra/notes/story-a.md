## Key-verse gating
Core sets the flag `restored.<shlokaId>` when a recital succeeds, at a plain shrine tile or through `{shloka, mode:'restore'}`. My gates test that flag, so a failed recital never opens a gate. A "keeper" NPC stands beside each gating shrine. Its event (helper `keeper()` in lib.py) works like this:
```
if restored.<id>:  if !<marker>: success lines, {set: <marker>}   else: "already whole" lines
else:              explain, choice [Recite it (sets tmp) | Not yet]
                   if tmp: {unset tmp}, {shloka:id, mode:'restore'}, if restored.<id>: success + {set: <marker>} else: kind retry line
```
`<marker>` is the walkthrough's expectFlag (world.test wants a flag that a `{set}` sets). It is only set when `restored.<id>` is true.

## Chapter flow / hand-offs
- `common.intro` runs at newGame (ch1 start: tamasa_ashrama (15,7)). It shows the title card, s-tapah-svadhyaya and s-ko-nvasmin, the tutorial, and the objective.
- ch1 → ch2: the Siddhashrama finale sets `ch1.complete`, then fade, `{warp: ayodhya_city 17,27}`, fade in, `{save}`. The script then ends, so the view's "chapter complete" panel shows next. The ch2 title card and intro (`ch2.intro`) run from a once-trigger block (rows 25-28 of ayodhya_city) on the player's **first step** in the next session. Every tile around the arrival tile is in that block, so it cannot be skipped.
- ch2 → ch3: the same pattern. The Chitrakuta duel win sets `ch2.complete` and warps to dandaka_vana (2,13); `ch3.intro` is a trigger block at x1-3, y9-18 there.
- The chapter intros are deliberately **not** `onEnter` events: they would play before the previous chapter's "complete" panel.
- Each chapter intro does `{rest:true}`, so a lost boss fight never respawns the player in an earlier chapter's map.
- **For story-b, ch3 → ch4:** shabari_ashrama's east warp at **(31,11)** → `rishyamuka (1,15) facing right`, `requires: ch3.complete`. The walkable tile next to it is **(30,11)**: point your return warp from rishyamuka (0,15) there. ch3 ends by setting `ch3.complete` in Shabari's event (`{rest}` and `{save}` follow). The party is player + rama + lakshmana at Pampa.
- **For story-b, epilogue:** tamasa_ashrama gets the npc `valmiki_epilogue` (sprite valmiki) at **(15,6)**, facing down, event `ch6.epilogue_valmiki`, `showIf: ch6.crowned`. My build adds it only when your event exists. My shrine Valmiki now has `showIf: ch1.duel_done&!ch6.crowned`. **Warp the player to (15,8) facing up.** That tile is on the path, two tiles below the npc.

## For view
- Speakers: `who` is a `person.<sprite>` name id for named characters (plus `portrait` = sprite). Generic NPCs use an English label (e.g. "Sage", "Merchant", "Disciple") plus a `portrait`. Narration has no `who`.
- `light`: dawn (tamasa_ashrama, tamasa_bank, siddhashrama_road), night (tataka_vana), dusk (shringaverapura, khara_camp, mriga_vana, jatayu_glade), interior (huts, palace, school), day elsewhere.
- Merchants stand next to (not behind) market stalls, so plain adjacent interaction works.
- Text uses `{n:move.*}` markup for the astra and verse-move names, and `{player}`.
