## For view

### Battle phases → the actions they accept (`state.battle.phase`)
| phase | the view shows | send |
|---|---|---|
| `intro`, `beats` | `battle.beats[0]` (text + `fx` + `sfx`, HP bars from `allyHp`/`foeHp`) | `advance` pops one beat |
| `command` | Fight / Switch / Item / Run | `choose 0..3` |
| `pick-move` | `battleMenu(state, content).moves` (`{id, pp, maxPp, usable}`) | `choose i` (index into `battle.ally.moves`), `choose -1` = back |
| `challenge` | `state.pending` = `{kind:'challenge', context:'battle'}` | `answer {option \| order, timeMs}` |
| `feedback` | `state.pending` = `{kind:'feedback'}` | `advance` resolves the turn (beats follow) |
| `pick-switch` | party list; `battleMenu().switchable` = party indexes allowed | `choose <party index>`; `-1` = back (ignored when `battleMenu().forcedSwitch`, i.e. the active hero is exhausted) |
| `pick-item` | `battleMenu().items` (item ids, defs order, qty > 0, no key items) | `choose i` (index into that list), `-1` = back |
| `won` / `lost` / `fled` | remaining beats | `advance`; when beats run out `battleOutcome()` is non-null and core ends the battle |

- In every phase except `challenge`/`feedback`, `state.pending` is `{ kind: 'battle' }`.
- Ignored actions return the **same object**.
- `battleMenu(state, content)` also gives `canRun` (wild only). Choosing Run when `canRun` is false (or Switch/Item with nothing available) adds an info beat and returns to `command` without costing a turn.
- Beat fx kinds: `hit` (amount, effective), `heal`, `buff`, `debuff`, `miss`, `faint`, `swift` (perfect fast answer, "Flawless"), `switch` (the ally sprite changes: `battle.ally` already holds the new hero), `flee`.
  `allyHp`/`foeHp` are snapshots *after* that beat's event. With multiple foes, `battle.foe` stays the fainted foe until its beats are consumed; the next foe arrives with its own intro beat.
- Beat text may contain `{player}` (the player's hero), `{n:ally.x}`, `{n:enemy.x}`, `{n:move.x}`, `{n:item.x}` and `{w:lexId}` (restored words).
- Who leads: in a duel the reciter (`player`) leads; otherwise the first conscious hero who is not the reciter (so Rama leads in ch1–4 without a wasted switch).
- **Relaxed setting**: logic has no settings. In Relaxed mode never time out and send `timeMs: 0`: any correct answer then counts as swift (DESIGN §4.3: swift = correct on the first try when untimed).
- Timeout: send `answer` with no `option`/`order` (graded wrong).
- `Challenge` rendering:
  - `artha`: `stimulus` (Devanagari lemma, user script) → `options[].en`.
  - `lipi`: `stimulusScript: 'iast'` with `options[].script: 'deva'`. If the user's script is IAST, swap them for display (show the stimulus in Devanagari and the options in IAST); the ids and answers do not change.
  - `purana`: `stimulus` = the pāda's words separated by spaces with `＿＿` for the gap. Options are Devanagari words.
  - `krama`: `tiles` (shuffled words). Accept the answer as `order` = tile indexes in the order tapped. `orders` lists every accepted order (duplicate words are interchangeable). Show `orders[0]` as the answer.
  - `viccheda`: `stimulus` = joined form; options are the split words separated by a space.
  - `vibhakti`: `stimulus` = a verse word (`shlokaId`, `padaIndex` tell you which verse/line, if you want to show the verse); options are English role labels.
  - `explanation` is English with `{w:lexId}` / `{n:kanda.N}` markup (verse references look like `{n:kanda.1} 1.2.15`).
  - L2 IAST hints on Devanagari stimuli are a view concern (`ctx.level === 2`).
- Equip menu: `learnableMoves(member, state.save, content)` (logic-progress) or core's `knownMoves`. They agree.
  Verse-unlocked moves are equipped automatically only while a hero has < 4 moves; otherwise a toast says "(equip it from the Party menu)".
- Explanations, toasts and beats never contain raw Devanagari/IAST, only markup.

## Learning details worth knowing
- `artha` asks the lemma → its English meaning. Proper names (`pos: 'name'`) are only asked when a script names them via `lexIds` (their "meaning" just restates the name).
- Word pool = words of heard verses + words with `seen > 0`; weight (6 − box) × recency × 2 for current-chapter verses. Leitner: correct +1 (max 5), wrong −2 (min 0).
- Stun: a hero bound by a faster foe loses that turn's action; bound by a slower foe, they lose the next turn, which resolves without a command. Nobody can be re-bound in the turn they recover.

## Deviations from DESIGN (balance / types)
- `aditya_hrdaya` has `effect` heal party 0.5 plus an optional JSON field `extraEffects: [buff-atk party +1]` (MoveDef allows one effect; logic-battle reads `extraEffects`).
- XP = DESIGN base `enemy.xp · L / 5` × max(1, (L/5)^0.95) × share (1 fought / 0.75 benched / 0.5 exhausted) × catch-up. Without the level factor the L^1.8 curve outruns the linear yield after ch2.
  Natural play (tested): 3–6 wild battles per chapter → within ±1 of the recommended levels; story battles only → at most 3 under; 10 per chapter → at most 2 over.
- "party" buffs raise the side's stages and carry over on Switch (the whole party is buffed).
- Secondary effects of damaging enemy moves (maya_jala's defence drop) fire 30% of the time; naga_pasha's stun rolls its own 0.3.
- When all of a hero's moves are at 0 PP, any move can still be chosen at half power ("weary") so a battle never stalls.
