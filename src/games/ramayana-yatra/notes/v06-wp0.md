## 1. Content loading (content.ts, logic-journey.ts)
- `assembleContent(parts)` / `bundledParts()` build the content; `loadContent()` = the bundled parts (cached).
- **Verses:** `shlokas-3/4/5.json` (A/B/C), schema of shlokas-1.json. The loader marks every one `kathaOnly: true` (write it
  anyway). A verse joins its book's `shlokaIds` in story order (`bookOrder`): after `storyAfter: "<id>"` when you give
  one (optional field), else before the first v0.5 verse of the book with a higher sarga.verse, else at the end.
- **Lexicon:** `lexicon-3/4/5.json`, **merged by id** (`mergeLexiconsV06`): an id that exists already only adds forms
  (same form + grammar → its shlokaIds merge into the existing form; else the form is appended, Kathā-only); its tags,
  notes and provenance are not used; lemma / pos / gender / meaning must agree (`lexiconConflicts`, v06-hooks.test). A new
  id is Kathā-only (entry and forms). After a lexicon change, regenerate `content/reader.json` (derived data, any package
  may): `RY_WRITE_READER=1 node --import tsx --test --test-name-pattern="basic words" src/games/ramayana-yatra/reader.test.ts`.
- **Anvaya + सरलार्थः:** `katha-verses-3/4/5.json` = `{ "version": 1, "verses": [ katha.json verse entries ] }` → appended to
  `content.katha.verses`. **Names:** `names-3/4/5/6.json` (A/B/C/D), new ids only, Kathā-only.
- **Review rows:** each content package keeps its verses' sign-off rows, its human-review items (`- **<id>**: …`) and its
  allowlist entries (`## Single-source items`, `## Sandhi-engine exceptions`: `- \`id\`: reason`) in its own
  `REVIEW-v06-<a|b|c>.md`; content.test / learning.test read them with REVIEW.md (no edit of content.test needed).
- **The Kathā-only filter** (`logic-journey`): `practiceContent(c)` is the content without v0.6 verses, Kathā-only
  entries / forms / shlokaIds and v0.6 names — exactly the v0.5 content. `journeyContent(c, save)` picks it for a practice
  save; `reduce`, `newGame`, `loadGame`, `sessionResult` apply it; Game.tsx gives the views `env.content` = the journey's
  content. Proof: v06-hooks.test "v0.6 guard" runs the V05A_PRACTICE walkthrough hash with synthetic v0.6 content loaded.
- **Restorable verses:** `isRestorable(c, id)` / `restorableIds(c, ids?)` — v0.5 verses only. A v0.6 verse is heard,
  never restored: the shrine neither lists nor accepts it (logic + view); HUD, book screens and the ending count
  "restored" against the restorable verses (heard counts against every verse).

## 2. The effects kit (event commands; logic-stage.ts → GameState.stage + 'kit' fx; view-stage.ts draws)
Kathā only (inside `{ "if": "style.katha", "then": [...] }`; world.test refuses them elsewhere; the practice journey skips
them). **None of them waits** — compose with `{ "wait": ms }`. Ids: npc ids of the current map, `"player"`, prop ids.
The stage lives while the script runs and is cleared when it ends (never saved). Every effect has a reduced-motion path.
```json
{ "if": "style.katha", "then": [
  { "fx": "flash" },
  { "fx": "shake", "ms": 1000 },
  { "topple": { "allBut": ["rama", "lakshmana", "vishvamitra_m", "janaka"] } },
  { "wait": 1200 },
  { "rise": "all" },
  { "fx": "petals", "ms": 6000 },
  { "fx": "tint", "color": "gold" },
  { "grow": "hanuman_m", "scale": 2.5 },
  { "glow": { "x": 12, "y": 7, "w": 2 }, "ms": 2500 },
  { "prop": "sandals", "sprite": "<PROP_ID | TileId | SpriteId>", "at": "rama" },
  { "prop": "sandals", "to": "bharata", "ms": 600 },
  { "prop": "sandals", "carry": "bharata" },
  { "arrow": { "from": "rama", "to": { "x": 30, "y": 6 }, "through": [{ "x": 18, "y": 6 }, { "x": 20, "y": 6 }] }, "ms": 700 },
  { "fx": "tint", "color": "none" },
  { "say": "…" }
] }
```
fx: shake / flash / petals / rain (`ms`), tint (`color`: gold, red, night, dawn, sea, none). topple / rise: `[ids]`,
`{ "allBut": [ids] }`, rise also `"all"`. grow: scale 0.5–4 (1 = normal). prop: place `at` (tile or figure), move `to`,
`carry` a figure (drawn over its head, follows it) or `null` (put down), `remove: true`; a prop can topple / grow too.
A tile glows for `ms`; an arrow flies from → through… → to (tiles or figure ids). e2e: `expose.stage` (down, scale, props,
tint), `expose.kitLog` / `window.__ryKitLog` (kit fx names), the canvas's `data-kit` (effects on screen now).

## 3. Hidden moments
- **In a script** (a held beat): `{ "hotspot": { "x": 12, "y": 7 }, "ms": 4000, "flag": "found.bow_mumble", "then": [ …lines… ] }`
  → pending 'hotspot': the last line stays, the tile shimmers; A (Z/Enter) or a tap on the scene finds it (its `flag`,
  default `found.<event id>`, then its `then`); ▶ / B passes; after `ms` (default 4000) it passes by itself. Bots pass it
  (logic-sim `hidden: true` / e2e Bot `findHidden: true` find it).
- **On a map** (discoverable, never on the main path): `MapDef.spots: [{ "x": 15, "y": 8, "event": "ch3.trees_remember",
  "requires": "style.katha&ch3.abducted&!ch3.trees_heard", "glow": true }]` — facing the tile (or standing on it) and A
  runs the event while `requires` holds (must include style.katha); `glow` shimmers it. The pointer and bots never go there.

## 4. Told cutscenes (logic-told.ts, view-told.tsx)
Files: `cutscene-mithila.json` (A), `cutscene-kumbhakarna.json` (C, optional), `cutscene-herbs.json` (D). A stub
(`"stub": true`, no steps) is skipped. Start one from a Kathā block: `{ "cutscene": "mithila" }` (the script waits;
then `seen.<id>` (or `flag`), the found hotspots' flags, the picked options' `set` are set and every verse on the played
path is heard). Format (types.ts ToldCutscene / ToldStep; positions are stage tiles 20 × 11.25, fractions allowed):
```json
{ "version": 1, "id": "mithila", "chapter": 1, "title": "Mithila", "painter": "a", "source": "Bāla 1.49–1.76",
  "steps": [
    { "scene": "road" },
    { "cast": "rama", "sprite": "rama", "at": { "x": 6, "y": 8 }, "face": "right" },
    { "cast": "vm", "sprite": "vishvamitra", "at": { "x": 4, "y": 8 } },
    { "say": "On the road to Mithila, Vishvamitra stops at an empty hermitage.", "who": "person.vishvamitra" },
    { "hotspot": "ahalya", "at": [14, 5, 2, 3], "ms": 8000, "then": [
      { "say": "…" }, { "verse": "s-ahalya" }, { "fx": "petals", "ms": 3000 } ] },
    { "scene": "sabha" },
    { "verse": "s-aropayitva", "padas": [0, 1, 2, 3] },
    { "fx": "flash" }, { "fx": "shake", "ms": 1000 },
    { "topple": { "allBut": ["rama", "lak", "vm", "janaka"] } },
    { "wait": 1200 }, { "rise": "all" },
    { "cast": "rama", "to": { "x": 9, "y": 8 }, "ms": 800 },
    { "prop": "bow", "sprite": "log", "at": { "x": 10, "y": 7 } },
    { "arrow": { "from": "rama", "to": { "x": 19, "y": 8 } } },
    { "ask": "…?", "options": [ { "label": "…" }, { "label": "…", "set": "ch1.x", "then": [ { "say": "…" } ] } ] }
  ] }
```
- `say`/`title`/`ask`/option labels/`who` (free English) are story strings: their Sanskrit goes in your dialogue file
  (A 10, C 12, D 13; the sambhashana test names what is missing). `verse` = a shlokaId; `padas` default all four.
- `scene` sets the painter's / 3D scene's shot (its own key; `ms` holds). Kit steps (fx, topple, rise, grow, glow, prop,
  arrow) and `cast` never wait; `wait` holds. A `hotspot` region is tappable (and key H) for `ms` (default 6000) while
  the next steps play; found → its `then` plays next. An `ask` stops the clock until one tap (keys 1–3); it sits at the
  top level only; an option's `then` plays next. `checkTold` (logic-told) validates a cutscene; v06-hooks.test runs it on
  every bundled cutscene.
- **Painters** (2D, 320 × 180): register in your `cutscene-paint-<x>.ts`: `export const PAINTERS_A = { a: (g, cue, art) => { … } }`.
  `cue` = { scene, t (ms in this shot), time, stage (cast, props, down, scale, tint), step, reduced, found, answers }.
  Paint the BACKDROP; the engine draws the cast, props and kit effects on top. With `cue.reduced` draw a still. Unknown /
  absent painter → 'plain' (a battle background when the shot key is a BATTLE_BG_ID, e.g. "palace", else a dusk wash).
- **3D (D):** `cutscene3d-herbs.ts` → `SCENES_D.herbs: Scene3DFactory` ((canvas, art, onLost) => { render(cue, frame),
  lost, dispose } | null); cue = { phase flat|rotate-out|scene|rotate-in|done, k, scene, t, progress, time, dt, stage,
  step, found, answers } (cutscene3d-scenes.ts). Used when `"scene3d": "herbs"`, WebGL works and motion is not reduced;
  else the 2D painter (`"painter": "d"`). D may add exports to cutscene3d.ts (not change the Āditya scene).
- Replay: the verse book (Menu → श्लोकाः) lists "‹title› ▶" for every cutscene seen (`told-replay-<id>`).
- e2e: `expose.told` = { id, replay }; root `[data-testid="told"]` with data-phase / data-step / data-ask / data-hotspot
  / data-mode / data-kit; `told-say`, `told-verse`, `told-pada-<i>`, `told-hotspot`, `told-ask`, `told-opt-<i>`, `told-pause`,
  `told-skip` → `told-skip-yes|no`. Fast in e2e (×60; `window.__ryCutsceneSpeed`), log in `window.__ryCutsceneLog`
  (`told|start|id`, `told|step|i|kind`, `told|hotspot|id`, `told|found|id`, `told|ask|k`, `told|answer|k|i`, `told|done|…`).
  `window.__ryTold(json)` registers a cutscene at run time (e2e only) — test yours before its JSON is final.

## 5. Verse echoes (C)
`content/katha-echoes.json`: `{ "version": 1, "echoes": [ { "id": "counsellors", "title": "v06c.echoCounsellors",
"shlokaIds": ["s-sulabhah-purusha", "…"], "source": "Araṇya 3.37.2 = Yuddha 6.16.21" } ] }` (`title` = a key of
sa-ui-v06-c.json). `{ "echo": "counsellors" }` in a Kathā block sets `echo.counsellors` once (toast with the title); the
verse book then shows "↺ ‹title›" under each of its verses (`echo-<id>`). `echoesOf(content, flags, shlokaId)`.

## 6. Bots and tests
- logic-sim: a 'cutscene' pending → `cutscene-done` (nothing found, first options; `hidden: true` finds every hotspot);
  'hotspot' → advance (or choose 0 with `hidden`). `runWalkthrough(REAL, seed, level, { style: 'katha', hidden: true })`.
- e2e-kit Bot: plays told cutscenes (answers via `toldAnswer(k)`, default 0; taps hotspots with `findHidden`) and passes /
  finds map hotspots. `planAt` saves hold the v0.5 verses only (never a "restored" v0.6 verse); `PRACTICE` = practiceContent.
- Art: `art-v06-<x>.ts`: `SPRITE_IDS_X` + `CHARS_X` (CharSpec; optional `BUILD_X` builder), `PROP_IDS_X` + `PROPS_X`
  (16 × 16 Pix painters). New sprite ids need `person.<id>` in your names file (content.test).
- WP0 tests: v06-hooks.test.ts (unit), world.test "validator self-test (v0.6)", sambhashana / sa-ui v0.6 tests,
  e2e-v06-wp0.spec.ts (told cutscene in संस्कृतम् with hotspot + question + replay; the kit + hotspot on the map;
  reduced motion + skip confirmation).
