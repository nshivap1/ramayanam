# tools/content/nominal — generators for the SHABDA and VOCAB packs

Nothing here ships to the browser. These scripts read reference datasets ("oracles"), derive / verify the
content packs and write generated TypeScript into `src/content/shabda/` and `src/content/vocab/`.

```
SAMSKURU_ORACLES=/path/to/refs/data   # default /home/claude/refs/data
node --import tsx tools/content/nominal/gen-shabda.ts            # → src/content/shabda/data.ts + reports/shabda-report.md
node --import tsx tools/content/nominal/gen-shabda.ts --check    # exit 1 if data.ts is stale
node --import tsx tools/content/nominal/gen-vocab.ts             # → src/content/vocab/data.ts + reports/vocab-report.md
node --import tsx tools/content/nominal/gen-vocab.ts --check
```

Only data files of the datasets are read; no code from them is executed. Expected layout under `$SAMSKURU_ORACLES`
(shallow clones named `<owner>_<repo>`):

| Directory | Used for | Files read |
|---|---|---|
| `ashtadhyayi-com_data` | declension tables generated by vidyut-prakriya; Amarakośa | `shabda/data2.txt`, `kosha/amara.json` |
| `sanskrit-lexicon_csl-inflect` | Sanskrit Heritage (Huet) declension tables; Cologne hand tables | `huetdata/nominals/huet_noun_tables.txt`, `nominals/pydecl/decline_{pron,card,irr}_data.txt` |
| `sanskrit_data` | learnsanskrit.org tables after Kale (CC0); Monier-Williams stem/gender list | `learnsanskrit.org/*.csv`, `monier-williams/nominal-stems.csv`, `monier-williams/indeclinables.csv` |
| `sanskrit-lexicon_csl-orig` | Monier-Williams and Apte dictionaries (lookup only, never vendored) | `v02/mw/mw.txt`, `v02/ap90/ap90.txt` |

## Files

- `shabda-spec.ts` — the hand-authored list of paradigms (stem, gender, meaning, level, source keys, reasoned exceptions). The only input you edit for SHABDA.
- `gen-shabda.ts` — builds every cell by two-family agreement (see `lib/derive.ts`), validates the Devanagari, writes `data.ts` and the report.
- `vocab-list.ts` — the hand-authored vocabulary list (word, gender, gloss, category, level, emoji). The only input you edit for VOCAB.
- `gen-vocab.ts` — checks every entry against the dictionaries, links declension models, writes `data.ts` and the report.
- `lib/oracles.ts` — dataset loaders (all forms normalised to one SLP1 spelling: pausa visarga, class nasals).
- `lib/derive.ts` — source resolution, voting, ordering of optional forms.
- `lib/slp.ts` — ṇatva rule and spelling normalisers. The ṇatva rule is itself tested against every table of ashtadhyayi.com (`src/content/shabda/oracle.test.ts`).
- `lib/dict.ts` — dictionary lookups for VOCAB.
- `reports/` — generated cross-check reports (commit them: they are the audit trail a reviewer reads).

## Rules the generators enforce

1. A declined form is kept only if two independent source families list it in that cell; with vidyut data present it must be one of them.
2. Single-family forms are dropped unless `shabda-spec.ts` accepts them with a written reason; all such cases are listed in the report and in `REVIEW.md`.
3. A paradigm with a cell that no two families agree on is dropped as a whole (reported).
4. A vocabulary noun is kept only if the stem **and its gender** are found in Monier-Williams, Apte or the Amarakośa; otherwise it must be explicitly
   marked as an established modern Samskrita Bharati coinage (`usage:samskrita-bharati`, level ≥ 1) — and its head (last member) must still be a dictionary word of that gender.
5. Generated files are never edited by hand; tests fail if they differ from a fresh generation.
