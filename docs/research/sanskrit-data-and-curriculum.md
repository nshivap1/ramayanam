# Samskuru — Sanskrit data, validation oracles, Samskrita Bharati curriculum map, accuracy risks

Research date: 2026-11-10. All clones are shallow (`--depth 1`) under `/home/claude/refs/data/<owner>_<repo>/`.
Nothing from any cloned repository was executed; files were only read. Analysis scripts are in
`/home/claude/work/scripts/` (run with `python3 -I` from outside the clones).

Conventions used in this report

- **VERIFIED** = I opened the file / fetched the page and saw it myself in this session.
- **UNVERIFIED** = from background knowledge or inference; not confirmed in this session.
- "Redistributable (commercial)" answers the question *may an open-source app ship a copy of this data, including if the app is ever used commercially?*
- Encodings: Deva = Devanāgarī, SLP1, IAST, HK = Harvard-Kyoto, WX.

Headline findings (read these first)

1. **Best single oracle for forms**: `ashtadhyayi-com/data` — 9,007 declension paradigms and 2,229 dhātus x 10 lakāras x 2 padas x kṛdantas, clean NFC Devanāgarī. But it is **generated by vidyut-prakriya**, so it is *not independent* of any engine built on vidyut, and its repo has **no LICENSE file** (README grants use "provided that appropriate credits are mentioned").
2. **Best independent second opinion**: INRIA Sanskrit Heritage forms as repackaged in `sanskrit/data` (LGPLLR licence) and `sanskrit-lexicon/csl-inflect` (LGPL-3.0). On 12,006 cells (210 "common" dhātus x 5 lakāras x padas) 91.7 % of the ashtadhyayi.com cells are found in Heritage; the misses I inspected were coverage differences (rare-but-valid Pāṇinian forms, prefixed roots), not contradictions.
3. **Licence traps**: Monier-Williams/Apte (Cologne) and all GRETIL texts are **CC BY-NC-SA** (non-commercial, share-alike). Gītā JSON repos carry permissive repo licences but bundle third-party modern translations whose rights are not cleared. Saṃskṛta-vyavahāra-sāhasrī online text is copyrighted, personal-study use only.
4. **Oracle cells are sets, not strings**: 43,254 of 254,736 verb cells and 9,128 of 216,168 noun cells contain alternatives, sorted so that the *first alternative is often the rare one* (`भवतात्,भवताद्,भवतु`; `आह,ब्रवीति`; `रामाद्-रामात्`). Display form and accept-set must be modelled separately.
5. The Samskrita Bharati per-level syllabus is only published at headline-topic level; the lesson-by-lesson contents of the printed books could not be confirmed online. The ladder in section 3 marks every row [C] confirmed / [K] background knowledge.

### 1.1 `ashtadhyayi-com/data` — primary oracle

URL: https://github.com/ashtadhyayi-com/data . README: "The entire data that powers https://ashtadhyayi.com is here."
Files are JSON with a `.txt` extension. All inspected strings are NFC, contain no ZWJ/ZWNJ, no nukta, and use
parasavarṇa nasals (`पञ्च`, `गच्छन्ति`), never `पंच` (scan of 9,007 + 28,304 + 50,705 strings; only 8 noun strings
have anusvāra before a stop, e.g. `चन्द्रसंज्ञः`).

Licence provenance: `vidyut-prakriya/data/README.md` in the vidyut repo states that the ashtadhyayi.com author
"has graciously agreed to share thse files with us under an MIT license" — that sentence covers the files vendored
into vidyut (dhātupāṭha, sūtra texts), not this whole repo.

**(a) `shabda/data2.txt`** (10.2 MB) — `{"name":"shabdapatha_v2","data":[ ... ]}`; **9,007 paradigms**
(liṅga `P` 4,791; `S` 2,108; `N` 2,106; `A` 2 = अस्मद्, युष्मद्). Every entry has exactly 24 `;`-separated cells:
index = (vibhakti-1)*3 + vacana, vibhakti 1..7 then sambodhana, vacana 0=eka 1=dvi 2=bahu. Alternatives inside a cell
are joined with `-`. Sambodhana cells carry a literal `हे ` prefix.

```json
{
  "urlid": "@a1",
  "word": "अ",
  "linga": "P",
  "artha": "विष्णुः",
  "artha_eng": "Lord Vishnu",
  "prakriya_options": { "linga": "P" },
  "forms": "अः;औ;आः;अम्;औ;आन्;एन;आभ्याम्;ऐः;आय;आभ्याम्;एभ्यः;आद्-आत्;आभ्याम्;एभ्यः;अस्य;अयोः;आनाम्;ए;अयोः;एषु;हे अ;हे औ;हे आः",
  "zbaseindex": "1.1"
}
```

Coverage VERIFIED present: राम, रमा, हरि (m and f), मति, नदी, गुरु, धेनु, वधू, पितृ, मातृ, कर्तृ, फल, वारि, मधु, राजन्,
आत्मन्, नामन्, मनस्, भगवत्, गच्छत्, विद्वस्, वाच्, गो, स्त्री, श्री, लक्ष्मी, सखि, पति, अक्षि, पथिन्, महत्, धनिन्;
pronouns तद्, एतद्, इदम्, किम्, यद्, अदस् (3 genders each), युष्मद्, अस्मद्, सर्व (m, n; feminine is a separate stem `सर्वा`),
भवत्; numerals एक, द्वि, त्रि, चतुर् (3 genders), पञ्चन्, षष्, सप्तन्, अष्टन्, नवन्, दशन्, विंशति, त्रिंशत्, चत्वारिंशत्, पञ्चाशत्.
**Missing** as headwords: `शत`, `सहस्र`, `एकादशन्` (and I did not find 11–19) — these need the engine or another source.

Caveats

- **Homonymous entries**: the same (word, liṅga) can occur twice with different grammar, e.g. `पूर्व` `@pUrva1`
  (sarvanāma: `पूर्वस्मै`, `पूर्वाः-पूर्वे`, `पूर्वे-पूर्वस्मिन्`) and `@pUrva3` (plain a-stem: `पूर्वाय`); likewise `पर`, `स्व`, `सम`,
  `भवत्` (`@bhavat1` भवान् = "you", `@bhavat2` भवन् = śatṛ of भू). **Key by `urlid`, never by (word, liṅga).**
- Optional forms are listed with the *d*-variant first: `रामाद्-रामात्`, `तद्-तत्`, `वाग्-वाक्`. The first alternative is not the textbook citation form.
- 55 entries have empty cells by design (द्वि only dual, त्रि… only plural, pronouns no vocative).
- `उभय` carries option `द्विवचनाभावः_कैयटः` yet still lists dual `उभयौ`; treat duals of उभय as disputed.
- `shabda/data_deprecated.txt` is an older 521-entry file; 419 of 501 comparable entries are identical to `data2.txt`; differences are mostly the homonym split above and rare bahuvrīhi stems (`सुसखि`, `प्रियत्रि`).
- Forms are generated by vidyut-prakriya (the `prakriya_options` keys are rule switches) -> not independent of vidyut.

**(b) `dhatu/data.txt`** (2.5 MB) — dhātupāṭha: **2,259 entries** (gaṇa 1: 1,166; 2: 77; 3: 26; 4: 163; 5: 38; 6: 174;
7: 25; 8: 10; 9: 71; 10: 509; pada P 1,132 / A 517 / U 580 / `-` 30 gaṇasūtras). 210 entries are tagged `common`
(by gaṇa: 94, 29, 7, 23, 7, 21, 7, 3, 12, 7). Field `dhaturoopnandini` (non-empty for 1,944) cross-references

**(c) `dhatu/dhatuforms_vidyut_shuddha_kartari.txt`** (9.7 MB) — object keyed by `baseindex`; **2,229 dhātus**; keys are
`p`/`a` (parasmai/ātmane) + lakāra: `plat plit plut plrut plot plang pvidhiling pashirling plung plrung` and the `a…`
equivalents (1,724 dhātus have `plat`, 1,101 have `alat`). Each value = 9 `;`-separated cells in order
prathama eka/dvi/bahu, madhyama eka/dvi/bahu, uttama eka/dvi/bahu; alternatives joined by `,`.

```json
"01.0001": {
  "plat": "भवति;भवतः;भवन्ति;भवसि;भवथः;भवथ;भवामि;भवावः;भवामः",
  "plit": "बभूव;बभूवतुः;बभूवुः;बभूविथ;बभूवथुः;बभूव;बभूव;बभूविव;बभूविम",
  "plrut": "भविष्यति;भविष्यतः;भविष्यन्ति;भविष्यसि;भविष्यथः;भविष्यथ;भविष्यामि;भविष्यावः;भविष्यामः",
  "plot": "भवतात्,भवताद्,भवतु;भवताम्;भवन्तु;भव,भवतात्,भवताद्;भवतम्;भवत;भवानि;भवाव;भवाम",
  "plang": "अभवत्,अभवद्;अभवताम्;अभवन्;अभवः;अभवतम्;अभवत;अभवम्;अभवाव;अभवाम"
}
```

Sibling files with the same shape: `…_shuddha_karmani.txt` (passive), and `nich` (causative), `san` (desiderative),
`yang`, `yangluk` x `kartari|karmani|krut` (6–17 MB each).

Caveats

- **Alternatives are sorted, not ranked**: `plot[0]` is `भवतात्,भवताद्,भवतु`; `ब्रू` `plat[0]` is `आह,ब्रवीति`; `विद्` `plat[0]` is `वेत्ति,वेद`. Never display "first alternative".
- Word-final `त्`/`द्` both listed (`अभवत्,अभवद्`) — the `द्` variant is a sandhi variant, not a separate answer to teach.
- **Homonymous roots**: three `इ` in gaṇa 2 (`02.0040` इण् गतौ, `02.0041` इङ् अध्ययने, `02.0042` इक् स्मरणे), two `पा`, two `शास्`, three `वृत्`. **Key by `baseindex`.**
- **Prefixes baked in**: `02.0041` gives `अधीते`, `02.0012` (आङः शासु) gives `आशास्ते`.
- **Over-generation relative to usage**: `स्था` (`01.1077`) has `pada: "P"` in `data.txt` but the forms file also contains `alat` `तिष्ठते…` (valid only with certain upasargas/senses). 13 `A` roots also have P forms, 6 `P` roots also have A forms. Filter by curriculum whitelist, not by presence in the file.
- 30 dhātupāṭha entries (gaṇasūtras) have no forms.

**(d) `dhatu/dhatuforms_vidyut_shuddha_krut.txt`** (6.4 MB) — keyed by `baseindex`; 2,229 dhātus; keys are pratyaya names in
Devanāgarī. Value = `prātipadika,puṃ,strī,napuṃsaka` (prathamā-ekavacana of each gender); indeclinables fill only the first slot;
alternative *derivations* are joined by `;`, alternative *forms* by `/`. `ल्यप्` forms use a dummy upasarga `प्र`.
Coverage: क्त, क्तवतु, ल्यप्, तुमुन्, तव्य, अनीयर्, ल्युट्, ण्वुल्, तृच्, क्तिन् … for all 2,229; क्त्वा 2,225; शतृ 1,724; शानच् 1,101;
also स्य-शतृ, स्य-शानच्, भावकर्म-शानच्, यत्, ण्यत्, क्यप्, घञ् ….

## 2. Recommended validation stack

Principle: Samskuru's own rule engines are the *system under test*. A form is shippable only if
(a) the engine output equals the **primary oracle** cell (set-equality on alternatives), and
(b) for content at levels L0–L3, at least one **independent** source also contains it, or a human reviewer has signed it off.
Because the primary oracle is vidyut-generated, an engine that itself wraps vidyut gets no assurance from (a) alone — (b) is then mandatory.

## 4. Accuracy-risk checklist — 25 ways Sanskrit games go wrong, each with a test

Notation: `f(x) -> y` is a test the suite should contain. "Oracle" = the ashtadhyayi.com files of section 2. Values marked (oracle) were read from those files in this session;
sandhi and metre expectations are standard grammar (my own derivation — have a grammarian countersign the golden file).

### A. Script, encoding, rendering

**1. Splitting by code point instead of akṣara.**
`संस्कृतम्` is 9 code points but 4 written units and 3 syllables; code that slices, reverses, shuffles or counts by code point (or by UTF-16 unit) breaks it.
- `codepoints("संस्कृतम्") -> 9`; `aksharas("संस्कृतम्") -> ["सं","स्कृ","त","म्"]`; `syllableCount("संस्कृतम्") -> 3`
- `aksharas("कार्त्स्न्यम्") -> ["का","र्त्स्न्य","म्"]` (13 code points; 2 syllables)
- `aksharas("क्षत्रियः") -> ["क्ष","त्रि","यः"]`
- Do not rely on the platform grapheme segmenter alone: engines with pre-15.1 Unicode data split after virāma (`स्` + `कृ`) [background knowledge]. Run the three tests above in every target browser.

**2. Normalisation: nukta letters and combining order.**
- `NFC("क़") -> "क़"` (the precomposed nukta letters U+0958–095F never survive NFC; VERIFIED with Python `unicodedata`)
- `NFC("क़्") -> "क़्"` (virāma and nukta are reordered; VERIFIED)
- `isSanskrit("ज़") -> false` (nukta has no place in classical Sanskrit input)
- `validate("कंि") -> reject` (anusvāra typed before the vowel sign; correct order is consonant, mātrā, anusvāra: `किं`)

**3. Look-alike sequences that normalisation does not fix.**
- `NFC("अ"+"ा") != "आ"` (VERIFIED: no canonical equivalence) -> `validate("अाम") -> reject or repair to "आम"`
- `validate("क"+"ा"+"े") -> reject` (renders like `को`)
- ASCII colon for visarga: `validate("राम:") -> reject or repair to "रामः"` — VERIFIED in the wild: `वाल्मीकि:`, `तप:` on 5,472 lines of the Rāmāyaṇa dataset.
- `|`, `||`, `।।` vs `।`, `॥` (VERIFIED in both Gītā datasets); ASCII digits vs `१२३`; apostrophe vs `ऽ`; `ॐ` vs `ओम्`. Pick one canonical form and test every imported corpus line against it.

**4. Anusvāra vs class nasal inside a word (parasavarṇa).**
The oracle writes `पञ्च`, `गच्छन्ति`, `गङ्गा`-style nasals; popular typing uses `पंच`.
- `equalAnswer("गंगा","गङ्गा") -> true`, `equalAnswer("पंच","पञ्च") -> true`, `display(...) -> "गङ्गा"`, `"पञ्च"`
- Must stay anusvāra (no class nasal exists): `canon("संस्कृतम्") -> "संस्कृतम्"`, `"सिंहः"`, `"वंशः"`, `"संयमः"`, `"हंसः"`; never `सन्स्कृतम्` / `सम्स्कृतम्`
- `equalAnswer("अंक","अङ्क") -> true` but `equalAnswer("अन्क","अङ्क") -> false`

**5. Word-final म् vs anusvāra.**
- `joinWords(["अहम्","गच्छामि"]) -> "अहं गच्छामि"`; `joinWords(["अहम्","अस्मि"]) -> "अहम् अस्मि"` (or `अहमस्मि`); `"अहं अस्मि" -> invalid`
- Sentence end: `"एतत् फलम्।" -> valid`, `"एतत् फलं।" -> invalid`
- Policy needed: Samskrita Bharati beginner style keeps words separate [K]; record the choice per level and test it.

**6. Avagraha.**
- `sandhi("रामः","अत्र") -> "रामोऽत्र"`; `toIAST("सोऽहम्") -> "so'ham"`; `fromIAST("so'ham") -> "सोऽहम्"`
- `syllableCount("सोऽहम्") -> 2`; `syllableCount("मा ते सङ्गोऽस्त्वकर्मणि") -> 8`
- VERIFIED variant in data: the vedicscriptures file writes the avagraha in roman as `.a` (`saṅgo.astvakarmaṇi`) — importer must map it.

**7. Conjunct vs virāma rendering, joiners, impossible clusters.**
- `containsJoiners(anyStoredString) -> false` (no U+200C/U+200D; the oracle files have none — VERIFIED)
- `validate("श्रृणोति") -> reject`; correct is `शृणोति` (oracle: `["01.1092"]["plat"][0] = शृणोति`); likewise `श्रृङ्गार` -> `शृङ्गार`
- `consonants("ज्ञानम्") -> ["ज्","ञ्","न्","म्"]`, `consonants("क्षमा") -> ["क्","ष्","म्"]` even if the tile shows one glyph
- Visual regression (screenshot diff) of a fixed conjunct sheet in the shipped font: `क्त द्ध द्य द्म द्व ह्म ह्य श्च श्र त्र ङ्क ङ्ग ञ्च ष्ट ष्ठ र्त्स्न्य`; word-final `म्`, `त्` must show a visible virāma.

### B. Transliteration

**8. Hiatus: अइ / अउ vs ऐ / औ.**
- `roundTrip_Deva_IAST_Deva("अइउण्") -> "अइउण्"` (first Māheśvara-sūtra; naive IAST `aiuṇ` returns `ऐउण्`)
- `roundTrip("प्रउग") -> "प्रउग"`, `roundTrip("तितउ") -> "तितउ"`
- Expected behaviour: emit an explicit separator (`a_i`, `aï`) or refuse to romanise; never lose the distinction. Note `common_maps/roman/iast.toml` maps `ï` as an alternate of `ī` (VERIFIED), so `aï` cannot be used with that map as is.

**9. Digraph ambiguity and scheme confusion ("ru" vs "ṛ").**
- `fromIAST("kṛṣṇa") -> "कृष्ण"`; `fromIAST("kruṣṇa") -> "क्रुष्ण"` (must not be auto-"corrected"); `detectScheme("krishna") -> not IAST`
- `detectScheme("dhṛitarāśhtra") -> not IAST` (VERIFIED in `gita/gita`); `detectScheme("vruddhiraadaich") -> not IAST` (VERIFIED in ashtadhyayi.com `sutraani/data.txt`)
- `"ऋषिः" != "रुषिः" != "रिषिः"`; `fromIAST("ṛṣiḥ") -> "ऋषिः"`
- Explicit virāma + ह: `roundTrip_Deva_SLP1_Deva("अग्हि") -> "अग्हि"` passes, but IAST `aghi` -> `अघि`; so use SLP1 (one character per sound) as the internal key and IAST only for display. (synthetic string)
- Accept both `ṃ` and `ṁ` on input (VERIFIED `ṁ` in the Rāmāyaṇa dataset); output one.

### C. Sandhi

**10. `सः` / `एषः` lose the visarga before any consonant.**
- `sandhi("सः","गच्छति") -> "स गच्छति"` (not `सो गच्छति`); `sandhi("एषः","बालकः") -> "एष बालकः"`
- `sandhi("सः","अपि") -> "सोऽपि"`; `sandhi("सः","इच्छति") -> "स इच्छति"`
- The CC0 rule table omits this by design (VERIFIED in its README); the sanskrit_parser rule file has it (`^[एष, स][ः, स्, र्] + …`).

**11. r-final words written with visarga (`पुनः`, `प्रातः`, `अन्तः`, vocatives `पितः`, `मातः`).**
- `sandhi("पुनः","अपि") -> "पुनरपि"` (not `पुनोऽपि`); `sandhi("प्रातः","एव") -> "प्रातरेव"`; `sandhi("अन्तः","गतः") -> "अन्तर्गतः"`
- `sandhi("पितः","अत्र") -> "पितरत्र"`; `sandhi("पुनः","रमते") -> "पुना रमते"`
- Needs a lexical flag on the word; cannot be derived from the surface string.

**12. Ordinary visarga sandhi traps (including `भोः`).**
- `sandhi("रामः","आगच्छति") -> "राम आगच्छति"` and the result must **not** be re-joined to `रामागच्छति`
- `sandhi("रामः","अस्ति") -> "रामोऽस्ति"`; `("रामः","गच्छति") -> "रामो गच्छति"`; `("रामाः","गच्छन्ति") -> "रामा गच्छन्ति"`
- `("हरिः","अस्ति") -> "हरिरस्ति"`; `("हरिः","रमते") -> "हरी रमते"`; `("रामः","च") -> "रामश्च"`; `("रामः","तिष्ठति") -> "रामस्तिष्ठति"`; `("रामः","करोति") -> "रामः करोति"`
- `sandhi("भोः","राम") -> "भो राम"`; `sandhi("भोः","अच्युत") -> "भो अच्युत"`

**13. Pragṛhya (no sandhi) — needs morphology, not strings.**
- `sandhi("हरी","एतौ", {left: dual}) -> "हरी एतौ"`; `sandhi("माले","इमे", {left: dual}) -> "माले इमे"`; `sandhi("अमी","अश्वाः") -> "अमी अश्वाः"`
- `sandhi("ते","एव", {left: m.nom.pl}) -> "त एव"` but `sandhi("ते","एव", {left: f/n.nom.du}) -> "ते एव"` (the vidyut-sandhi README uses this very example)

**14. Vowel-sandhi special cases.**
- `sandhi("महा","ऋषिः") -> "महर्षिः"`; `sandhi("देव","इन्द्रः") -> "देवेन्द्रः"`; `sandhi("इति","आदि") -> "इत्यादि"`
- Upasarga + verb: `("उप","एति") -> "उपैति"` (not `उपेति`); `("प्र","एजते") -> "प्रेजते"` (not `प्रैजते`); `("प्र","ऋच्छति") -> "प्रार्च्छति"`
- `sandhi("ते","अत्र", {pl}) -> "तेऽत्र"`; `sandhi("विष्णो","इह") -> "विष्ण इह"` (or `विष्णविह`)

**15. Consonant sandhi: doubling, inserted sibilants, optional nasalisation.**
- `("तस्मिन्","एव") -> "तस्मिन्नेव"` but `("तान्","एव") -> "तानेव"` (doubling only after a short vowel)
- `("तान्","च") -> "तांश्च"`; `("तान्","तान्") -> "तांस्तान्"`; `("तान्","लोकान्") -> "ताँल्लोकान्"`
- `("तत्","च") -> "तच्च"`; `("तत्","टीका") -> "तट्टीका"`; `("तत्","लीनः") -> "तल्लीनः"`; `("तत्","हितम्") -> "तद्धितम्"`; `("तत्","शिवः") -> accept {"तच्छिवः","तच्शिवः"}`
- `("वाक्","मयम्") -> "वाङ्मयम्"`; `("जगत्","नाथः") -> "जगन्नाथः"`; `("वृक्ष","छाया") -> "वृक्षच्छाया"`; `("सम्","कृतम्") -> "संस्कृतम्"`
- Real-text sanity: `("तस्मिन्","इति") -> "तस्मिन्निति"` (VERIFIED as line 2 of the sanskrit_parser passing set).

### D. Form generation

**16. ṇatva.**
- `inst_sg("राम") -> "रामेण"`, `gen_pl("राम") -> "रामाणाम्"` (oracle) vs `inst_sg("देव") -> "देवेन"`, `gen_pl("देव") -> "देवानाम्"` (oracle)
- `"पुष्पेण"`, `"पुष्पाणि"`, `"पुष्पाणाम्"` (oracle) vs `"वनेन"`, `"वनानि"` (oracle); `"हरिणा"`, `"गुरुणा"`, `"नेतॄणाम्"`, `"चतुर्णाम्"`, `"कर्मणा"`, `"ब्रह्मणि"` (oracle)
- Blocked by an intervening palatal/retroflex/dental/ल/श/स: `inst_sg("रथ") -> "रथेन"`, `("अर्जुन") -> "अर्जुनेन"`, `("रस") -> "रसेन"`, `("दर्शन") -> "दर्शनेन"`; word-final never: `acc_pl("राम") -> "रामान्"` (oracle)
- Participles: `"गृह्यमाणः"`, `"स्मर्यमाणः"`, `"चोरयमाणः"` vs `"लभमानः"`, `"दीयमानः"` (oracle)
- **Prefix trap**: the oracle stores `ल्यप्` of नी as `प्रणीय` and of नम् as `प्रणम्य` (ṇatva caused by `प्र`). Swapping the dummy prefix must re-run ṇatva: `lyap("आ","नी") -> "आनीय"`, `lyap("प्र","नी") -> "प्रणीय"`.

**17. ṣatva.**
- `loc_pl`: `"रामेषु"`, `"हरिषु"`, `"गुरुषु"`, `"नेतृषु"`, `"स्त्रीषु"` vs `"रमासु"`, `"राजसु"`, `"कर्मसु"`; `loc_pl("मनस्") -> accept {"मनःसु","मनस्सु"}` (all oracle)
- Future: `"भविष्यति"`, `"नेष्यति"`, `"लेखिष्यति"` vs `"दास्यति"`, `"पास्यति"` (oracle)
- Upasarga: `("नि","सीदति") -> "निषीदति"`; `("अभि","सिञ्चति") -> "अभिषिञ्चति"`; `("वि","स्मरति") -> "विस्मरति"`; `("अनु","सरति") -> "अनुसरति"`

**18. Optional forms (vikalpa): accept every valid answer, display one.**
Oracle cells with alternatives: `रामाद्-रामात्`; `मतये-मत्यै`; `मतौ-मत्याम्`; `मम-मे`; `तुभ्यम्-ते`; `राज्ञि-राजनि`; `नाम्नि-नामनि`; `एतम्-एनम्`; `स्त्रियम्-स्त्रीम्`; `श्रियाम्-श्रीणाम्`;
`अष्ट-अष्टौ`; `पठतात्,पठताद्,पठतु`; `रुन्द्धः,रुन्धः`; `वेत्ति,वेद`; `आह,ब्रवीति`; `धावति,सरति`; ktvā of इष्: `इष्ट्वा` / `एषित्वा`; lyap of गम्: `प्रगत्य` / `प्रगम्य`.
- `isCorrect(abl_sg("राम"), "रामात्") -> true` and `(…, "रामाद्") -> true`
- `isCorrect(dat_sg("मति"), "मत्यै") -> true`; `isCorrect(loṭ_3sg("पठ्"), "पठतात्") -> true`
- `preferred(loṭ_3sg("पठ्")) -> "पठतु"`; `preferred(laṭ_3sg("ब्रू")) -> "ब्रवीति"`; `preferred(laṭ_3sg("सृ")) -> "सरति"` — i.e. **never "first alternative"** (the oracle sorts alphabetically).
- Distinguish true vikalpa from pure sandhi variants (`अभवत्` / `अभवद्`): the latter should not be shown as "another answer".

**19. Syncretism: one form, several correct analyses.**
- `analyses("ते") ⊇ {तद् m.1.pl, तद् f.1.du, तद् f.2.du, तद् n.1.du, तद् n.2.du, युष्मद् 4.sg, युष्मद् 6.sg}` (all in the oracle)
- `analyses("रामाभ्याम्") = {3.du, 4.du, 5.du}`; `analyses("रामयोः") = {6.du, 7.du}`; `analyses("फलम्") = {1.sg, 2.sg}`
- `analyses("भवति") ⊇ {भू laṭ 3.sg, भवत् 7.sg}` (oracle: `@bhavat1` cell 18 = `भवति`); `analyses("गच्छति") ⊇ {गम् laṭ 3.sg, गच्छत् 7.sg}`
- A "which vibhakti?" question must accept any member, or the item must carry disambiguating context.

**20. Agreement: gender, number, person — including mixed gender and भवान्.**
- `"सः गतवान्"`, `"सा गतवती"`, `"बालकाः गतवन्तः"`, `"बालिकाः गतवत्यः"` valid; `"सा गतवान्" -> invalid`
- First person past depends on the speaker: `accept("अहं गतवान्") and accept("अहं गतवती")` unless the persona's gender is fixed
- `"भवान् कुत्र गच्छति?" -> valid`; `"भवान् कुत्र गच्छसि?" -> invalid`
- Numerals: `"द्वौ बालकौ"`, `"द्वे बालिके"`, `"द्वे फले"`; `"त्रयः बालकाः"`, `"तिस्रः बालिकाः"`, `"त्रीणि फलानि"`; `"चतस्रः बालिकाः"` (oracle forms `द्वौ/द्वे`, `त्रयः/तिस्रः/त्रीणि`, `चत्वारः/चतस्रः/चत्वारि`); `"त्रयः बालिकाः" -> invalid`
- No vocative for pronouns (oracle cells empty): generator must not emit `हे सः`
- Mixed gender: pronoun/participle for (रामः, सीता) is masculine dual — `"रामः सीता च गतवन्तौ"`, `"तौ"`; `"ते गतवत्यौ" -> invalid`

**21. Pada (P/Ā), homonymous roots, over-generation.**
- `laṭ_3sg("लभ्") -> "लभते"`; `"लभति" -> invalid`; likewise `"वन्दते"`, `"सेवते"`, `"वर्तते"`, `"मोदते"` (oracle `alat` only)
- `laṭ_3sg("कृ") -> accept {"करोति","कुरुते"}` (ubhayapadī)
- Lookup by `baseindex`: `forms("इ")` is ambiguous — `02.0040` `एति…`, `02.0041` `अधीते` (prefix included), `02.0042`
- Whitelist test: `isTaughtForm("तिष्ठते", level<=L3) -> false` although the oracle has it; `isTaughtForm("तिष्ठति") -> true`
- Gaṇa labels: the oracle files `श्रु` under gaṇa 1 (`01.1092`, `शृणोति`) while school grammars list it under the 5th class — do not expose raw gaṇa numbers without review.

**22. Augment, upasarga, and ktvā vs lyap.**
- `laṅ_3sg("इष्") -> "ऐच्छत्"` (oracle `ऐच्छत्,ऐच्छद्`); `laṅ_3sg("अस्") -> "आसीत्"` (oracle); not `अइच्छत्` / `अअस्त्`
- Augment goes after the prefix: `laṅ("उप","विश्") -> "उपाविशत्"`; `laṅ("अनु","गम्") -> "अन्वगच्छत्"`; `laṅ("प्र","विश्") -> "प्राविशत्"`; `laṅ("निर्","गम्") -> "निरगच्छत्"`; `laṅ("आ","गम्") -> "आगच्छत्"`
- `gerund("गम्") -> "गत्वा"`; `gerund("आ","गम्") -> accept {"आगत्य","आगम्य"}`; `"आगत्वा" -> invalid`; `"गम्य" -> invalid`; negative `gerund("अ","कृ") -> "अकृत्वा"` (नञ् is not an upasarga); `gerund("प्र","कृ") -> "प्रकृत्य"` (oracle)
- No guṇa in 6th-class presents: `"लिखति"` (not `लेखति`) but future `"लेखिष्यति"` (oracle)

### E. Metre

**23. Laghu/guru decided across word boundaries, not per word.**
- `scan("न त्वेवाहं जातु नासं") -> G G G G G L G G` (`न` is guru because the next word begins with `त्व`)
- `scan("धर्मक्षेत्रे कुरुक्षेत्रे") -> G G G G L G G G`; in isolation `scan("कुरु") -> L L`
- Visarga and anusvāra close the syllable: `scan("रामः") -> G G`; `scan("संस्कृतम्") -> G L G`
- Scan the whole pāda as one string after removing spaces, daṇḍas, digits, avagraha.

**24. Pāda-final syllable (anceps) and metres that are not fixed patterns.**
- `identify("वासांसि जीर्णानि यथा विहाय") -> Indravajrā pāda` although it scans `G G L G G L L G L G L` against the table's `GGLGGLLGLGG` (VERIFIED pattern in `meters.tsv`); the last light syllable counts as heavy.
- Upajāti: a verse mixing Indravajrā and Upendravajrā pādas must be reported as Upajāti, not "unknown".
- Anuṣṭubh is rule-based (5th light, 6th heavy in every pāda; 7th heavy in odd, light in even pādas) with accepted vipulā variants; it is absent from `meters.tsv` (VERIFIED). `identify("वागर्थाविव सम्पृक्तौ वागर्थप्रतिपत्तये । जगतः पितरौ वन्दे पार्वतीपरमेश्वरौ ॥") -> "अनुष्टुप् (श्लोक)"` (VERIFIED as the first case in `chandasIdTests.json`).
- `scan("मा ते सङ्गोऽस्त्वकर्मणि") -> G G G G L G L L` (8 syllables).
- Mātrā metres (Āryā 12-18-12-15) need mora counting, not pattern lookup.

### F. Data hygiene

**25. Trusting source files as-is.**
- Oracle cell parsing: `parseCell("हे राम") -> "राम"` (strip the vocative particle); `parseCell("तद्-तत्") -> {"तद्","तत्"}`; `parseCell("गतवत्,गतवान्,गतवती,गतवत्/गतवद्") -> stem + 3 genders`; `parseCell("प्रगत्य,,,;प्रगम्य,,,") -> 2 derivations`.
- Raw comparison files are pre-sandhi: `sanskrit/data` stores `akzinI` for अक्षिणी and `Bavatas` for भवतः (VERIFIED) — `compare(normalize(x))`, never raw.
- Third-party sandhi sets contain wrong gold (`vidvāḥ+atha`, `अक्ष+ऊहिन्यः` — VERIFIED): never auto-promote corpus pairs into the golden suite.
- Old vs new files in the same repo disagree (`प्रशीय` vs `प्रशय्य` — VERIFIED): pin file names as well as commits.
- Homonymous oracle entries (`@pUrva1` vs `@pUrva3`): `forms({word:"पूर्व", linga:"P"})` must return **both** or require a `urlid`; test `isCorrect(dat_sg("पूर्व"), "पूर्वस्मै") -> true`.
- Corpus punctuation and numbering (`।।1.1।।`, `||१-१||`) must be stripped before metre or akṣara games.

Further candidates if the list is extended: clock-time compounds (`पादोनषड्वादनम्` for 5:45 [K]); alternative number names (19 = `नवदश` / `एकोनविंशतिः` / `ऊनविंशतिः` [K]);
feminine of present participles (`गच्छन्ती`, `तुदती/तुदन्ती` (oracle), `ददती`, and the `याती`/`यान्ती` question flagged in 1.1); kāraka items with more than one valid case (`विना` with 2nd/3rd/5th [K]).
